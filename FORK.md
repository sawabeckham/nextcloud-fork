# Nextcloud Fork

Клиент Nextcloud для Mac, в котором **диск в Finder** («Места», File Provider) и **обычная синхронизация
выбранных папок** работают одновременно. В официальном клиенте это два взаимоисключающих режима:
при включении File Provider подключения папок удаляются.

Основа рабочего дерева — `nextcloud/desktop` v35.0.1 (официальный commit `ad4a8503bcbb1749ea4f5955a65688cbe32305df`). Изменения форка — в ветке `fork`.
Последняя выпущенная версия форка — `0.6.4` (установлена; hostname-only подпись Finder проверена после перезапуска). Исходники содержат Unreleased для целевой `0.6.5`; метаданные пока сохраняют `0.6.4` по [политике выпуска](doc/DEVELOPMENT.md). Единственный источник версии — `FORK_VERSION.cmake`. Версия основы хранится отдельно в `VERSION.cmake`.
Компоненты версии форка — три цифры; после `0.6.9` идёт `0.7.0`. CMake добавляет суффикс `fork0.6.4` к версии основы и выводит build number `64` из цифр версии форка; его получают также Xcode-расширения.

## Что изменено

- Сборочный флаг `NEXTCLOUD_EXPERIMENTAL_HYBRID_SYNC` (`src/common/hybridsyncpolicy.h`): при включении File Provider
  подключения папок остаются, окно «выберите один режим» не появляется, панель папок в настройках аккаунта видна.
  Без флага поведение как у официального клиента.
- Папку для обычной синхронизации нельзя выбрать внутри `~/Library` (там хранилище File Provider —
  `~/Library/CloudStorage`) и нельзя выбрать саму домашнюю папку или её родителей
  (`src/common/hybridsyncpaths.h`, `src/gui/macOS/hybridsyncpaths.h`). Такие уже настроенные папки пропускаются при запуске.
- Флаг `NEXTCLOUD_FORK`: своё имя «Nextcloud Fork», bundle ID `site.manro.nextcloudfork`, свои настройки и запись
  в Связке ключей, схема ссылок `nextcloudfork://`, без автообновления официального клиента.
  Официальный Nextcloud.app и его аккаунты не затрагиваются.
- Сборка пакета: библиотеки клиента копируются в `Contents/Frameworks` до `macdeployqt`.
- Значки — оригинальные Nextcloud с надписью «fork»: значок приложения (Dock, Finder;
  `theme/colored/NextcloudFork-macOS-icon.svg`), монохромные значки строки меню, как у официального клиента,
  с «fork» под символом (`theme/*/nextcloudfork/`), и символ диска в «Местах»
  (`FileProviderExt/Assets.xcassets/FileProviderForkSymbol.symbolset`, задаётся `OC_FILE_PROVIDER_SYMBOL`).
  В версии 0.6.0 цветной синий градиент форка — `#4295F5` → `#145CC5`, вместо исходных голубых градиентов Nextcloud. Значки ошибки/предупреждения и чёрные/белые значки сохраняют прежние цвета. Исходные ресурсы Nextcloud не перекрашиваются.
  Их рисует `swift admin/fork/make-fork-icons.swift` из оригинальных файлов; значки строки меню
  квадратные — Qt вписывает значок в квадрат. Finder кэширует значки «Мест»: после смены — `killall Finder`.
- Домен File Provider называется только адресом сервера (`files.example.org`, с портом, если он
  нестандартный) — так называется папка диска в `~/Library/CloudStorage` (`src/common/forkdomaindisplayname.h`).
  Если адрес оканчивается на расширение пакета вроде `.app`, остаётся имя «сервер - пользователь»: иначе Finder
  показал бы папку диска как программу. В боковой панели Finder при одном диске пишет имя приложения
  («Nextcloud Fork»), а не имя домена. На 01.11.2026 это подтверждено в работающем Finder: корень имеет путь `NextcloudFork-files.romanenko.online`, но в заголовке и «Местах» виден `Nextcloud Fork`; поле переименования корня в свойствах отключено. В macOS 27.2 исследованный FileProviderDaemon скрывает domain display name при количестве доменов меньше двух (кроме системного iCloud); поддерживаемый override для форка пока не найден. Подробности и границы — [исследование](doc/MACOS_FINDER_LOCATION_NAMING.md). Задача владельца остаётся открытой; переименование домена само по себе её не решает.

Ограничение: по словам разработчиков Nextcloud, пока работает расширение File Provider, macOS не запускает
расширение FinderSync. Тогда у обычных папок не будет значков состояния и пунктов в контекстном меню Finder,
но синхронизация будет идти. На деле это ещё не проверено.

Одни и те же файлы сервера можно открыть и через диск, и через синхронизируемую папку. Если править
файл в обоих местах одновременно, получится конфликт (Nextcloud сохранит обе версии).

## Сборка

```
./build.sh                       # тесты + клиент + расширения + PKG; автоматической установки нет
SKIP_EXTENSIONS=1 ./build.sh     # только клиент, быстрее
```

Зависимости — из Homebrew (Qt 6.12, cmake, KArchive, QtKeychain, libp11, librsvg и др., список — `BREW_DEPS`
в `build.sh`; если чего-то нет, скрипт скажет, что поставить). KDSingleApplication в Homebrew нет — `build.sh`
собирает её сам из релиза v1.2.1 на GitHub.

По умолчанию результаты лежат в `~/Library/Caches/RomanenkoSources/nextcloud-fork/releases/0.6.4`: `package/Nextcloud Fork.app`, журналы в `logs` и сборочная копия `Nextcloud-Fork-0.6.4-arm64.pkg`. После упаковки проверенная побайтно копия установщика автоматически сохраняется также в `~/Github_local/pkg` — это общая папка PKG всех программ владельца. Для форка там остаются текущая и одна предыдущая версия; старые пакеты других программ не затрагиваются. Каталог можно задать через `BUILD_DIR`, уже установленную сборочную зависимость — через `KDSA_PREFIX`. Старый каталог `.../nextcloud-fork/package` не используется новой сборкой по умолчанию. `NO_INSTALL=1` остаётся совместимым параметром, но запуск установки теперь всегда выполняется отдельно.

## Установка и обновление приложения

Откройте `Nextcloud-Fork-0.6.2-arm64.pkg` штатным Installer macOS. Пакет устанавливает приложение в `/Applications/RomanenkoApp/Nextcloud Fork.app`, требует права администратора и поддерживает Apple Silicon/macOS 13+. До установки завершите форк через меню; официальный Nextcloud закрывать не требуется. Preinstall отказывает, если процесс `Nextcloud Fork` ещё запущен, целевой путь является симлинком или выбран другой том. Он не завершает синхронизацию принудительно.

После установки запускайте приложение из `Программы → RomanenkoApp`. Бандл не следует запускать из build/cache. Настройки и идентификаторы форка сохраняются; installer не удаляет аккаунты, домены и пользовательские файлы и не запускает приложение автоматически. Postinstall регистрирует приложение и расширения в контексте текущего console user; при отсутствии пользователя регистрация откладывается до первого запуска. Принудительного включения расширений нет.

`admin/fork/publish-installer.py` копирует готовый пакет через временный файл, проверяет SHA-256 и атомарно публикует новое имя без перезаписи. Одинаковый файл допускает повторный вызов; другие байты под уже опубликованной версией требуют новой версии. Симлинки/пустые файлы и откат на более старую версию отклоняются.

`admin/fork/make-installer.py` использует системные `ditto`, `codesign`, `pkgbuild` и `productbuild`. Существующий upstream pipeline (`admin/osx/create_mac.sh.cmake`, `macosx.pkgproj.cmake`) зависит от стороннего `packagesbuild`, устанавливает в `/Applications` и содержит скрипты с путём официального клиента. Для независимого назначения форка добавлен небольшой отдельный упаковщик; проверка console user основана на `admin/osx/post_install.sh.cmake` с сохранением авторства Nextcloud/ownCloud.

Упаковщик принимает только настоящий бандл `Nextcloud Fork.app` с ID `site.manro.nextcloudfork`, версией текущего форка, тремя расширениями с ID форка и действующей проверкой `codesign --verify --deep --strict`. Содержимое подписанного приложения не редактируется. Component plist запрещает relocation, включает проверку версии и ID и замену старого бандла при обновлении. Это не позволяет Installer перенаправлять установку на обнаруженную копию в кэше. Существующий выходной PKG упаковщик не перезаписывает; `build.sh` сохраняет предыдущий результат как `.previous`.

```sh
python3 admin/fork/make-installer.py --app '/path/to/Nextcloud Fork.app' --output '/path/to/Nextcloud-Fork-0.6.2-arm64.pkg'
```

Нужен Python 3.9+. Необязательный `--sign` принимает доступный сертификат Developer ID Installer. Apple Development подпись приложения не является подписью установщика и не обеспечивает нотариализацию. Без Developer ID Installer создаётся локальный неподписанный PKG с подписанным приложением внутри. `UNSIGNED=1 ./build.sh` создаёт только приложение для разработки, без PKG.

Профильные проверки запускаются через `cmake -S test/hybrid -B build/fork-policy -G Ninja -DCMAKE_PREFIX_PATH=/opt/homebrew`, `cmake --build build/fork-policy`, `ctest --test-dir build/fork-policy --output-on-failure`. `ForkInstaller` создаёт и распаковывает настоящий PKG с тестовым ad-hoc бандлом, проверяет путь, отсутствие relocation, payload/signature и отказ для другого ID/старой версии/неполного бандла/изменённой подписи/симлинка/выхода внутри бандла. Это не заменяет проверку установки с правами администратора и запуска живого File Provider. `ForkPalette` вызывает функцию перекраски на исходных синих цветах, проверяет сохранение status/mono, пустой ввод и повторное применение; результат PNG осматривается отдельно.

## Подпись

`build.sh` подписывает пакет сертификатом «Apple Development» Personal Team Apple ID (`TEAM_ID`, по умолчанию
`EW76LLFDSH`): порядок и флаги как в `admin/osx/mac-crafter` (изнутри наружу, hardened runtime, entitlements из сборки).
Профиль подготовки не нужен: в entitlements нет ключей `com.apple.developer.*`, только песочница, сеть и группа
приложений `EW76LLFDSH.site.manro.nextcloudfork`. Сертификат создаётся в Xcode → Settings → Apple Accounts →
Personal Team → Manage Certificates → + → Apple Development. `UNSIGNED=1 ./build.sh` — без подписи.

Подпись разработчика не нотаризована. Запуск на другом Mac в этом этапе не проверялся; Apple Development не заменяет Developer ID/нотариализацию для обычного распространения.

## Обновление до новой версии Nextcloud

Включён ежедневный мониторинг в этом чате Codex на 10:00 Europe/Moscow (automation `nextcloud-macos`). Он проверяет стабильные upstream releases и существенные исправления macOS/File Provider/безопасности, сообщает о новых значимых изменениях и ошибках проверки, не переносит код и не устанавливает обновления автоматически. При неизменном состоянии уведомлений нет. Расписание хранится в Codex, не в Git.

На 01.11.2026 официальный [latest release — v35.0.1](https://github.com/nextcloud/desktop/releases/tag/v35.0.1), опубликован 29 октября. В его описании есть изменения File Provider, XPC ARC, сетевых тайм-аутов, Keychain и работы с симлинками. В этапе 0.6.1 перенесён исходный diff `v35.0.0...v35.0.1` с сохранением изменений форка; защищённые translations и AGENTS не заменялись. Полная сборка и PKG созданы, дополнительные проверки продолжаются. Установлена 0.6.2; runtime проверка ещё продолжается. Проверка синхронизации на тестовом аккаунте остаётся отдельным этапом.

История форка начинается с локального snapshot-коммита `8a53276`, а не полной upstream history. Ветка `upstream` локально отсутствует. Старую команду rebase не применять без сверки графа и ref: сначала получить нужные теги и проверить соответствие деревьев, затем выбрать перенос diff или rebase в отдельной ветке. Рабочие незакоммиченные изменения предварительно сохранить.

## История

### 0.6.4 — 2026-11-01 (установлена)

- По уточнению владельца подпись Finder должна содержать только hostname: без префикса Nextcloud Fork. Имя приложения сохраняется.
- Fork-only `NSFileProviderHideExtensionName` в NSExtension FileProviderExt; системный код этой macOS читает Boolean key и использует имя домена вместо составного provider/domain имени. Параметр не найден в публичной документации Apple; совместимость других версий требует проверки. Системные API/entitlements и реальные аккаунты не меняются.
- Проверки, фактический статус установки и следующая работа — последние разделы doc/CURRENT_STATE.md и doc/MACOS_FINDER_LOCATION_NAMING.md. Реальный Finder показал только files.romanenko.online; после штатного перезапуска клиента результат сохранился.

### 0.6.3 — 2026-11-01 (установлена, подпись Finder проверена)

- Скрытый служебный File Provider domain с отдельным ID включает multi-domain подпись при одном настоящем аккаунте. В установленной копии Finder показал «Nextcloud Fork - files.romanenko.online»; результат сохранился после штатного перезапуска. Видимая строка форка одна.
- Пустые read-only item/enumerator и ранние guards расширения исключают account/credential/service workflow этого домена.
- Клиент управляет только точным служебным ID, с асинхронным чтением регистрации, ограниченными повторами, защитой от коллизии account mapping и от перекрытия native mutations после timeout. Настоящие домены для косметики не пересоздаются.
- Условия, источники системного поведения, тесты и оставшиеся проверки — doc/MACOS_FINDER_LOCATION_NAMING.md и doc/CURRENT_STATE.md. App name сохраняется Nextcloud Fork.

### 0.6.2 — 2026-11-01 (предыдущая; подпись Finder не исправлена)
- Для точного bundle ID форка корневой File Provider item получает display-only filename из существующего domain.displayName (адрес без схемы). WebDAV metadata, raw filename `/` и идентификатор корня сохраняются; обычные items и официальный bundle сохраняют прежнее поведение.
- Имя входит в metadataVersion корня, сохраняя contentVersion; metadata-only modification сохраняет имя. Добавлены шесть XCTest cases с успешными/invalid/default/ordinary-item/branding/lifecycle/version сценариями.
- Полный Swift с явным `--no-parallel`: 388 XCTest, 1 ожидаемый skip, 0 ошибок; 101 Swift Testing прошли. Default concurrent Swift Testing один раз упал в общем NKLogFileManager при создании тестовых расширений, это не исправлено и не скрывается.
- Consuming build и PKG прошли, 0.6.2 установлена. Реальная строка Finder с **одним** подключением осталась Nextcloud Fork, несмотря на hostname в root metadata. Причина и границы — doc/MACOS_FINDER_LOCATION_NAMING.md.
- Исправлены bundle IDs всех macOS test apps: отдельное пространство .tests.<target>, regression test проверяет runtime identity и native domain isolation. Сохранённые после побочного эффекта прежних тестов локальные данные скопированы отдельно; подробности инцидента и восстановления — doc/CURRENT_STATE.md.

### 0.6.1 — 2026-11-01 (предыдущая установленная версия)
- Основа 35.0.1: исправления upstream File Provider, XPC, Keychain, синхронизации и интерфейса; сохранены авторство и лицензии Nextcloud/ownCloud и других исходных компонентов. Защищённые переводы не обновлялись.
